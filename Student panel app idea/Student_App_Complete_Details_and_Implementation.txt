1. EXECUTIVE OVERVIEW & OBJECTIVE
--------------------------------
The SmartAttend Student App is an independent, mobile-first Android application
designed to isolate the student experience from the unified web system. The app
communicates directly with the production Render backend and Supabase PostgreSQL
database. The existing web student panel remains 100% active and untouched during
a phased soak-testing period to guarantee zero disruption to daily academic operations.

4. AUTHENTICATION & SECURE SESSION LIFECYCLE
--------------------------------------------
• Dual-Storage Auth : Credentials (`smartattend_token`, `studentId`, `studentName`, `studentEmail`,
  `studentDept`, `studentSem`) are persisted in both `sessionStorage` and `localStorage`.
  This allows sessions to survive mobile app termination and restarts.
• Auth Guards       : In-line JavaScript guards check authentication state prior to DOM render;
  unauthenticated visitors are immediately bounced to `index.html`.
• Global Interceptor: `backend/config.js` wraps `window.fetch` to automatically append
  `Authorization: Bearer <token>` on all outbound API requests.

5. 5-CATEGORY BOTTOM NAVIGATION ARCHITECTURE
--------------------------------------------
The dashboard was restructured from a long scrolling page into 5 dedicated categories:

• Tab 1 — Overall Attendance & Smart Analytics:
  - Dynamic Chart.js donut chart with animated percentage counter.
  - Safe / Below 75% threshold badge with dynamic color transitions.
  - Attended vs Total class metrics and subject-by-subject breakdown tables.
  - Smart Recovery Insights: Calculates exact classes needed to attain 75% or classes safe to miss.

• Tab 2 — Live Lab Session Attendance:
  - Dynamic 6-digit session PIN check-in with uppercase formatting and letter-spacing.
  - Anti-Proxy Device Fingerprinting: Device UUID saved in local storage prevents multi-account proxying.
  - "Mark Present" Button: Optimized vertical height (`min-height: 48px; padding: 13px 26px; border-radius: 12px;`)
    keeping horizontal width compact (`width: auto;`) with spinner loading states.

• Tab 3 — Medical & Leave Requests:
  - Segment 1: Leave application form (Medical, Duty, Casual) with PDF/image attachment uploads.
  - Segment 2: Real-time Leave Request Status History tracker (`Pending`, `Approved`, `Rejected`)
    with date-range filtering.

• Tab 4 — Class Timetable:
  - Day-wise period schedule cards populated dynamically by student department and semester.

• Tab 5 — Class Assignments:
  - Assignment due dates, submission links, and dynamic multi-level semester/subject filters.

6. IN-APP DIRECT DATA REFRESH ENGINE
------------------------------------
• 1-Tap Topbar Refresh  : Circular spinning button (`#refreshBtn`) in the top navigation bar.
• Pull-to-Refresh Gesture: Native touch gesture on `.dashboard-container` allowing users to swipe down
  to reload live attendance metrics without restarting the app.
• Floating Toast Feedback: Emerald green floating toast confirmation ("Data refreshed successfully!").

7. DUAL-MODE HARDWARE NAVIGATION COMPATIBILITY (3-BUTTON VS GESTURE)
-------------------------------------------------------------------
• Root Cause Solved  : Fixed height (`height: 66px`) with `box-sizing: border-box` caused Android's
  3-Button Navigation bar inset (`safe-area-inset-bottom`) to squish content height down to ~32px.
• Dynamic CSS Solution:
  - `.bottom-nav`: `min-height: 64px; height: calc(64px + env(safe-area-inset-bottom, 0px));`
    with `padding-bottom: env(safe-area-inset-bottom, 0px); align-items: flex-start;`
  - `.nav-tab`: Locked fixed height to `64px`, keeping icons and labels perfectly centered.
  - `.dashboard-container`: Bottom padding set to `calc(90px + env(safe-area-inset-bottom, 0px))`.
  - Viewport Meta: Added `viewport-fit=cover` so WebView accurately calculates Android display bounds.
• Result             : Identical visual rendering on Realme Narzo 50A and other Android devices
  under both 3-Button mode and full-screen Gesture mode.

8. MODERN ANDROID BUILD & APK SIGNING PIPELINE
----------------------------------------------
• Target Platform   : Android 11+ (API 30–36) running on physical mobile devices.
• Uncompressed ARSC : Preserved `resources.arsc` with uncompressed STORED storage to satisfy Android OS rules.
• 4-Byte ZipAlign   : Aligned uncompressed assets to 4-byte boundaries using `uber-apk-signer`.
• Multi-Scheme Sign : Applied APK Signature Schemes [v1, v2, v3] using RSA-384 and custom `debug.keystore`.
• Outcome           : Resolved WhatsApp download / OS "App not installed" package parsing errors.

9. CLOUD BACKEND & LIVE SYNCHRONIZATION
---------------------------------------
• Host Backend      : Render Production Server (`https://smartattend-o2te.onrender.com`).
• Database          : Supabase PostgreSQL (handling students, attendance logs, leaves, timetables).
• Parity Guarantee  : Mobile app actions write to the exact same database records as the professor portal.

10. TESTING PROTOCOL & PHASED WEB DECOMMISSIONING
