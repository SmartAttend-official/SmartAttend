1. WHAT IS TWO-FACTOR AUTHENTICATION (2FA)?
================================================================================

Two-Factor Authentication (2FA) is an extra security layer added to both the
professor login system AND the admin login system. Normally, a user only needs
an email + password to log in. With 2FA enabled, after entering the correct
email and password, the user must also enter a 6-digit One-Time Password (OTP)
that is sent to their registered email address.

This means even if someone steals a password, they still cannot log in without
also having access to the registered email inbox.

─── PROFESSOR 2FA ───

WITHOUT 2FA:
  Professor enters Email + Password  -->  Login Granted  -->  Dashboard

WITH 2FA ENABLED:
  Professor enters Email + Password
      |
      v
  Server verifies credentials (correct)
      |
      v
  Server generates 6-digit OTP  -->  Sends to professor's email
      |
      v
  Login page shows OTP entry panel with countdown timer
      |
      v
  Professor enters 6-digit OTP from email
      |
      v
  Server verifies OTP + checks it is not expired (10-minute window)
      |
      v
  JWT token issued  -->  Login Granted  -->  Professor Dashboard

─── ADMIN 2FA ───

WITHOUT 2FA:
  Admin enters Email + Password  -->  Login Granted  -->  Admin Dashboard

WITH 2FA ENABLED:
  Admin enters Email + Password
      |
      v
  Server verifies credentials (correct)
      |
      v
  Server generates 6-digit OTP  -->  Sends to admin's email (amber styled)
      |
      v
  Admin login page shows OTP entry panel (amber/gold theme)
      |
      v
  Admin enters 6-digit OTP from email
      |
      v
  Server verifies OTP + checks it is not expired (10-minute window)
      |
      v
  JWT token issued  -->  Login Granted  -->  Admin Dashboard

2. HOW IT WORKS — PROFESSOR'S PERSPECTIVE
================================================================================

ENABLING 2FA:
  1. Log in to SmartAttend as a professor.
  2. Go to the Profile page (sidebar: Profile icon).
  3. Scroll down to "Notification Preferences" card (on the right column).
  4. Find the "Two-Factor Authentication" toggle at the bottom of that card.
  5. Toggle it ON (it turns green with checkmark).
  6. A confirmation message appears: "2FA enabled — OTP required on every login."
  7. From this moment, every login will require an OTP.

DISABLING 2FA:
  1. Go to Profile page (same as above).
  2. Find the "Two-Factor Authentication" toggle.
  3. Toggle it OFF.
  4. Confirmation message: "Two-Factor Authentication disabled."
  5. From this moment, login goes back to email + password only.

LOGGING IN WITH 2FA ACTIVE:
  1. Open Login.html (Professor login page).
  2. Enter your university email and password. Click "Sign In".
  3. If 2FA is enabled, the login form disappears.
  4. An OTP panel slides in showing:
       - A shield icon and "Two-Factor Authentication" heading
       - Your email address (masked, e.g. am***@gmail.com)
       - Six individual digit boxes (6-digit OTP entry)
       - A 10:00 countdown timer
       - "Verify OTP" button
       - "Resend OTP" link
       - "Back to Login" link
  5. Check your email inbox for the OTP.
  6. Type the 6 digits (each box auto-advances to the next).
     OR paste the entire 6-digit code — it fills all boxes automatically.
  7. If all 6 digits are entered, it auto-submits without clicking the button.
  8. If OTP is correct and not expired:
       Button turns green  -->  "Access Granted"  -->  Redirects to Dashboard.
  9. If OTP is wrong: boxes turn red, shake, clear. Try again.
  10. If OTP expires (10 minutes passed): Click "Resend OTP" for a new one.
  11. If you want to try a different account: Click "Back to Login".

KEY BEHAVIOURS:
  - Default State      : OFF for all professors (no 2FA unless manually enabled)
  - Persistence        : Setting saved permanently in database. Survives logout,
                         page refresh, and server restart.
  - Scope              : Each professor controls their own 2FA independently.
  - OTP Validity       : 10 minutes from time of sending.
  - OTP Length         : 6 digits (numeric only).
  - Auto-Submit        : OTP auto-submits when all 6 digits are entered.
  - Resend Rate Limit  : Cannot spam resend — same anti-spam rules as password
                         reset OTPs.
  - Stays ON/OFF       : Once enabled, stays ON forever until professor turns it
                         OFF manually. No auto-reset on logout.

3. DATABASE CHANGES (SUPABASE)
================================================================================

─── PROFESSOR TABLES ───

A new column was added to all four professor department tables:

  Column Name  : TwoFactorEnabled
  Data Type    : BOOLEAN
  Default      : FALSE (2FA is OFF for all existing professors by default)
  Tables       : BCA, MCA, BBA, MBA

SQL that was executed in Supabase Dashboard -> SQL Editor:

  ALTER TABLE "BCA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
  ALTER TABLE "MCA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
  ALTER TABLE "BBA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
  ALTER TABLE "MBA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;

─── ADMIN TABLE ───

Three new columns were added to the ADMIN table:

  Column Name  : TwoFactorEnabled
  Data Type    : BOOLEAN NOT NULL
  Default      : FALSE (2FA is OFF for admin by default)
  Table        : ADMIN

  Column Name  : OTP
  Data Type    : TEXT, nullable
  Purpose      : Stores the pending 2FA OTP during admin login flow
  Table        : ADMIN

  Column Name  : OTP_Timestamp
  Data Type    : TEXT, nullable
  Purpose      : Stores OTP expiry time (ISO string, 10 min from generation)
  Table        : ADMIN

SQL to run in Supabase Dashboard -> SQL Editor:

  ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" boolean NOT NULL DEFAULT false;
  ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "OTP" text;
  ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "OTP_Timestamp" text;

To verify all columns exist, run in Supabase SQL Editor:

  SELECT column_name, data_type, column_default
  FROM information_schema.columns
  WHERE table_name IN ('BCA','MCA','BBA','MBA','ADMIN')
  AND column_name IN ('TwoFactorEnabled','OTP','OTP_Timestamp')
  ORDER BY table_name, column_name;

ENDPOINT 1: verify_login_otp  (Professor)
--------------------------------------------------------------------------------
Method     : POST
URL        : https://smartattend-o2te.onrender.com/
Auth       : None required (public endpoint — professor has no JWT yet)
Purpose    : Verify the 2FA OTP entered by professor during login

Request Body:
  {
    "action": "verify_login_otp",
    "email": "professor@university.edu",
    "otp": "123456"
  }
  (role field optional for professor — defaults to professor)

Success Response (200):
  {
    "status": "success",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "sessionToken": "17503924821abc123xyz",
    "user": { ...professor data without password... }
  }

Error Response — Wrong OTP (401):
  { "status": "error", "message": "Invalid OTP. Please try again." }

Error Response — Expired OTP (401):
  { "status": "error", "message": "OTP has expired. Please log in again." }

Error Response — User Not Found (404):
  { "status": "error", "message": "User not found." }

7. SECURITY DESIGN
================================================================================

  OTP Length          : 6 digits (1,000,000 possible combinations)
  OTP Expiry          : 10 minutes from time of generation
  OTP Storage (Prof)  : Stored in professor's dept table (OTP + OTP_Timestamp)
  OTP Storage (Admin) : Stored in ADMIN table (OTP + OTP_Timestamp columns)
  OTP Cleared On      : Successful verification (immediately cleared from DB)
  OTP Single-Use      : After one successful use, OTP is deleted — cannot be
                        reused (replay attack protection)
  JWT Issuance        : JWT is only issued AFTER 2FA verification.
                        Password alone does NOT issue a JWT when 2FA is ON.
  Session Token       : Professor: new SessionToken generated after 2FA.
                        Admin: sessionToken is null (admin uses simple JWT).
  Rate Limiting       : Same per-email OTP rate limiter as password reset
                        (prevents email bombing / OTP spam abuse).
  IDOR Protection     : toggle_2fa (professor) compares JWT email with target.
                        toggle_admin_2fa (admin) checks ADMIN table directly.
  No Bypass           : When 2FA is ON, there is no way to skip the OTP step
                        through the normal login flow.
  Brute Force         : 10-minute expiry limits brute force attempts.
  Role Routing        : verify_login_otp and resend_2fa_otp both accept a
                        "role" field — routes to admin or professor logic.
  Auth Bypass List    : verify_login_otp and resend_2fa_otp are in the public
                        auth bypass list so users can call them before JWT.

PROBLEM 1: Toggle turns ON but shows error "The TwoFactorEnabled column does not exist"
CAUSE   : The ALTER TABLE SQL was not run in Supabase yet.
SOLUTION: Open Supabase Dashboard -> SQL Editor and run:
          ALTER TABLE "BCA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
          ALTER TABLE "MCA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
          ALTER TABLE "BBA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;
          ALTER TABLE "MBA" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" BOOLEAN DEFAULT FALSE;

PROBLEM 2: OTP email not received after enabling 2FA and logging in
CAUSE   : Email delivery issue.
SOLUTION: 1. Check spam/junk folder.
          2. Test email delivery: open in browser:
             https://smartattend-o2te.onrender.com/?action=debug_email&to=YOUR_EMAIL
          3. Verify SMTP_PASS in server/.env is the correct Gmail App Password.

PROBLEM 3: "OTP expired" message
CAUSE   : More than 10 minutes passed since the OTP was sent.
SOLUTION: Click "Resend OTP" on the login screen. A fresh OTP will be sent.

PROBLEM 4: Entering correct OTP but getting "Invalid OTP" error
CAUSE   : You may have clicked "Resend OTP" — each resend generates a NEW OTP.
SOLUTION: Use only the most recently received OTP email.

PROBLEM 5: Toggle stays OFF even after enabling it (professor)
CAUSE   : Either the API call failed, or TwoFactorEnabled column does not exist.
SOLUTION: Open browser DevTools -> Console -> check for error messages.
          If column missing, run the SQL (Problem 1 fix above).

─── ADMIN 2FA ISSUES ───

PROBLEM 6: Admin 2FA toggle shows "The TwoFactorEnabled column does not exist in the ADMIN table"
CAUSE   : The ALTER TABLE SQL has not been run for the ADMIN table in Supabase.
SOLUTION: Open Supabase Dashboard -> SQL Editor and run:
          ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "TwoFactorEnabled" boolean NOT NULL DEFAULT false;
          ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "OTP" text;
          ALTER TABLE "ADMIN" ADD COLUMN IF NOT EXISTS "OTP_Timestamp" text;
          Direct link: https://supabase.com/dashboard/project/kuqynurnkslvultxzzen/sql/new

PROBLEM 7: Admin 2FA toggle shows "Checking status..." and never updates
CAUSE   : GET request for get_admin_2fa_status may be failing or unauthorized.
SOLUTION: 1. Make sure you are logged into admin panel (JWT must be valid).
          2. Check browser DevTools -> Network for the GET request.
          3. Verify ADMIN table has TwoFactorEnabled column (Problem 6 above).

PROBLEM 8: Admin logs in without OTP even though 2FA toggle is ON
CAUSE   : Server may not have latest code, or TwoFactorEnabled not saved.
SOLUTION: 1. Push latest code to GitHub and wait for Render to redeploy.
          2. Verify in Supabase:
             SELECT "Email", "TwoFactorEnabled" FROM "ADMIN" WHERE "Email" = 'admin@email.com';
          3. Ensure value is boolean TRUE (not string "true").

PROBLEM 9: "Back to Login" not visible on admin OTP screen
CAUSE   : Screen height issue.
SOLUTION: Scroll down on the login panel. The link is below Resend OTP.

PROBLEM 10: Professor can log in without OTP even though 2FA is enabled
CAUSE   : Server may not have the latest code deployed yet.
SOLUTION: Push the latest code to GitHub. Render will auto-deploy.
          Also verify TwoFactorEnabled = TRUE (boolean) in Supabase table.

10. FUTURE IMPROVEMENTS (PLANNED)
================================================================================

The following features are NOT currently implemented but are planned for future:

  1. Backup Codes
       Generate 10 single-use backup codes professors can print or save.
       Useful if they lose access to their email.

  2. Lockout on Repeated Wrong OTPs
       After 5 consecutive wrong OTP attempts, temporarily lock the account
       (5–15 minutes) to prevent brute force attacks.

  3. Trusted Devices
       Allow professor to mark their browser/device as "trusted for 30 days".
       On trusted devices, the 2FA OTP step is skipped automatically.

  4. TOTP / Authenticator App Support
       Support Google Authenticator / Authy as an alternative to email OTP.
       Professor scans QR code once and uses app-generated codes to login.

  5. SMS Fallback
       If professor cannot access email, allow OTP delivery via SMS to their
       registered mobile number as a fallback.

  6. Admin Force-Enable 2FA
       Allow admin to force-enable 2FA for ALL professors institution-wide
       from the admin dashboard (currently each professor decides individually).

  7. 2FA Login History
       Show professor their last 5 successful 2FA logins (timestamp + IP + device)
       on their profile page for security awareness.

  8. OTP Delivery Status
       Show the professor a real-time delivery status when OTP is being sent
       (e.g., "Sending..." spinner before the OTP panel appears).

12. ADMIN 2FA — STEP-BY-STEP HOW IT WORKS
================================================================================

ENABLING ADMIN 2FA:
  1. Log in to the Admin Dashboard.
  2. Click "My Profile" in the sidebar (or profile dropdown at top right).
  3. The Profile page opens. Click the "Two-Factor Auth" tab
     (4th tab in the left nav, after Activity Analytics).
  4. The tab loads and automatically fetches your current 2FA status.
  5. You will see the card: "Email OTP Verification" with a toggle.
  6. Click the amber toggle to turn it ON.
  7. A success message appears: "Two-Factor Authentication enabled."
  8. From this moment, every admin login will require an email OTP.

DISABLING ADMIN 2FA:
  1. Go to Admin Dashboard -> My Profile -> Two-Factor Auth tab.
  2. Click the amber toggle to turn it OFF.
  3. Success message: "Two-Factor Authentication disabled."
  4. Admin login goes back to email + password only.

LOGGING IN AS ADMIN WITH 2FA ACTIVE:
  1. Open admin_login.html.
  2. Enter your admin email and password. Click "Verify & Enter".
  3. If 2FA is enabled, the login form disappears.
  4. An amber-themed OTP panel slides in showing:
       - Lock icon (🔐) with amber gradient background
       - "Two-Factor Authentication" heading
       - Your email address (masked, e.g. ad***@gmail.com)
       - Six individual digit boxes (6-digit OTP entry)
       - A 10:00 countdown timer
       - "Verify OTP" button
       - "Resend OTP" link
       - "Back to Login" link
  5. Check your email inbox for the OTP (amber-styled admin email).
  6. Type the 6 digits (each box auto-advances).
     OR paste the entire 6-digit code.
  7. If all 6 digits filled, it auto-submits.
  8. If OTP is correct and not expired:
       Button turns green --> "Access Granted" --> Admin Dashboard.
  9. If OTP wrong: boxes turn red, shake, clear. Try again.
  10. If OTP expires: Click "Resend OTP" for a new one.
  11. Click "Back to Login" to use a different account.
