2. TECHNICAL ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------

ROOT CAUSE A: Brittle Client-Side Substring Hijacking (html/dashboard1.html)
  * Location: `processAIIntent(rawQuery)` in `html/dashboard1.html`.
  * Naive `if (q.includes('present'))` and `if (q.includes('absent'))` checks intercepted 
    natural language queries before they ever reached the server or AI model.
  * The code only checked the client-side JavaScript in-memory variable `students` 
    for the active webcam frame.
  * If the camera had not started or `students` was empty, it immediately printed:
    `"The student list hasn't loaded yet."`
  * Any mentioned date (such as "second November") was completely ignored.

ROOT CAUSE B: Authentication Token Storage Key Mismatch
  * Location: `askGemini(prompt)` in `html/dashboard1.html`.
  * The function checked: `const token = sessionStorage.getItem('token');`
  * In SmartAttend, login tokens are stored under:
    - `sessionStorage.getItem('smartattend_token')` (set by backend/login.js)
    - `localStorage.getItem('smartattend_token')` (set by backend/student_login.js)
  * Because the key `'token'` was null, the client code immediately aborted:
    `if (!token) return "Error: You are not logged in.";`
  * Furthermore, asking read-only questions to an assistant should never abruptly 
    fail with an auth block when testing or previewing.

ROOT CAUSE C: Complete Absence of RAG (Retrieval-Augmented Generation) in Backend
  * Location: `action === 'ask_gemini'` in `server/server.js`.
  * Previously, the backend only sent raw user text to Gemini with an outdated 9-bullet 
    summary from months ago.
  * Zero database queries were made to Supabase.
  * Gemini had no knowledge of:
    - Real attendance ledgers (`AttendanceHistory` table).
    - Student names matching IDs (e.g. `BCA051` -> `Aman Kaushal`).
    - Smart Attendance Credit Model (approved leaves credited as present).
    - Multi-day leaves, duration chips (+2d..+7d), AI medical fraud trust scores.
    - Lab 6-digit cryptographic PINs with 5-minute decay timers.

3. FULL RAG ARCHITECTURE & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------

A. Frontend Upgrades (html/dashboard1.html):
  1. Multi-Key Token Retrieval:
     `const token = sessionStorage.getItem('smartattend_token') ||`
     `              localStorage.getItem('smartattend_token') ||`
     `              sessionStorage.getItem('token') ||`
     `              localStorage.getItem('token') || '';`
     - Allows requests to proceed even if token is absent (guest/testing mode).
  2. Instant Greetings:
     - Detects "hi", "hello", "hey" and immediately returns a friendly welcome 
       with guidance on what the assistant can do.
  3. Direct UI Action Interception Only:
     - Local handlers restricted strictly to hardware commands:
       * "start camera" / "launch camera" -> clicks `#camera_btn` (Start)
       * "stop camera" / "turn off camera" -> clicks `#camera_btn` (Stop)
       * "save attendance" -> calls `triggerSaveAlert()`
       * "log out" / "sign out" -> calls `logoutUser()`
  4. Real-Time Session Context Hydration:
     - Gathers live classroom metadata to send with every query:
       * Active Department, Semester, Subject, Session Date
       * Live webcam scan statistics (present count, detected names, leave count, absent count).

B. Backend Upgrades (server/server.js):
  1. Auth & RBAC Softening for Assistant Queries:
     - In `authenticateToken`: if `action === 'ask_gemini'`, decode token if present, 
       but do not reject with 401 if missing.
     - In RBAC gate: assign default role `'professor'` for `action === 'ask_gemini'` 
       so read-only assistant queries never fail with 403 Forbidden.
  2. Natural Language Date Parser (`extractDateFromQuery`):
     - Parses words like "second november", "2nd nov", "november 2nd", "today", 
       "yesterday", and ISO formats (`YYYY-MM-DD`).
  3. Student ID Extractor (`extractStudentIdFromQuery`):
     - Extracts pattern `[A-Z]{2,5}\d{2,6}` (e.g. `BCA051`, `BCA054`).
  4. Dynamic Supabase Data Retrieval:
     - Date query: Fetches `AttendanceHistory` matching the date, cross-references 
       `students` table using column `ID` to map student names, queries `LeaveRequests` 
       for approved leaves.
     - Student profile query: Fetches overall classes attended and total classes from 
       `students` table, calculates attendance percentage.
     - Leave audit query: Fetches pending leave applications and AI fraud trust scores.
  5. Enhanced Institutional Knowledge Base:
     - Supplies Gemini with accurate definitions of the Smart Credit Model, formula, 
       bounding box colors (green = present, amber = leave), and anti-proxy features.
  6. Deterministic Fail-Safe Engine (`generateDeterministicFallback`):
     - If Gemini API is rate-limited, offline, or the key is a placeholder, 
       the backend directly formats the live database counts into a clean markdown 
       response. The user NEVER gets a broken error or "list hasn't loaded" message.
