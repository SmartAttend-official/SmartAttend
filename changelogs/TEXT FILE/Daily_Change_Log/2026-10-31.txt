WHAT WAS FIXED
--------------
Enforced one-attendance-per-subject-per-day rule for both classroom
(Face Scan) and lab attendance. A second submission for the same subject
on the same day is now fully rejected at the backend.

CHANGES MADE
------------
File: server/server.js
  - Added in-memory lock (_savingSessionLocks) to prevent race conditions
  - Duplicate check uses Date + Subject only (removed Semester filter
    which caused false negatives due to string format mismatch)
  - dupCheckErr set to non-fatal (logs warning, continues) to avoid
    blocking valid first-time sessions on transient Supabase errors
  - Per-student UPDATE path removed — existing records are skipped (never overwritten)
  - ROOT CAUSE FIX: Changed .select('ID') → .select('StudentID') in both
    duplicate check queries. 'ID' column does not exist in AttendanceHistory,
    causing every check to fail silently.

Files: html/dashboard1.html, html/Lab_Attendance.html
  - Added specific handler for result.duplicate === true
  - Shows clear "Attendance Already Marked" message instead of generic error

FINAL BEHAVIOUR
---------------
  ✅ Subject → 1st time today         → Saved
  ❌ Subject → 2nd time same day      → REJECTED (clear message shown)
